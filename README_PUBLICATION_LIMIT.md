# 無料プラン：企業募集1件・求人募集3件／予約公開への対応

2026-11-21に添付されたバックエンド／フロントエンドを基準とした変更です。JDK 25・Spring Boot 3.5.16など、添付版のバージョン設定は維持しています。

## 適用する順序

1. バックエンドを停止します。
2. A5:SQL Mk-2で対象のPostgreSQLに接続し、`db/004_publication_plans_A5MK2.sql` を全文実行します。単体配布の `GlobalWorkers_publication_plans_A5MK2.sql` も同じ内容です。両方を実行する必要はありません。
3. 修正版バックエンドを展開して起動します。
4. 修正版フロントエンドを展開して起動します。

新規DBの場合は、先に `db/GlobalWorkers_create_tables_A5MK2.sql`、続いて004を実行してください。基礎DDLは既存テストの実行にも使用するため同梱しています。

SQLは通常のPostgreSQL SQL文で、DO文・ドル引用符・関数作成は使いません。再実行できます。既存の会社や記事を削除しません。

## 初回に既存データへ適用する制限

すべての既存企業を無料プランへ登録し、企業募集は1件、求人募集は3件まで、それぞれ独立して公開できます。企業募集1件＋求人募集3件の同時公開が可能です。各区分で上限を超えている場合は、その区分の更新日時が新しいものを上限件数分だけ残し、超過分を公開停止（BLOCKED）としてアラート表示します。記事内容は残り、編集できます。非表示・開始前・終了済みは枠を消費しません。

新規企業も最初は無料プランです。企業オーナーと、その企業に所属する従業員は同じ掲載枠を共有します。一般ユーザーや他社の件数は混ぜません。

## 作成・更新

- 同じ募集区分の公開中件数で判定します。企業募集は1件、求人募集は3件が上限です。
- 編集中の募集自身は数えません。上限件数を公開中でも、そのうち1件の編集は可能です。募集区分を変更した場合は、変更先の区分の枠で判定します。
- 上限に達している場合は「非公開で保存する」「保存せず編集を終了」「編集に戻る」を表示します。選択前は登録・更新しません。
- 予約公開日時がある場合は「予約公開する」「非公開で保存する」「編集に戻る」を表示します。
- 非公開で保存した求人は掲載枠を消費しません。日付が来ても勝手に公開されません。
- 保存直前に他の操作で満枠になった場合も、サーバー側で拒否し、画面で再度確認します。

## 公開予定の日時

既存の開始日に「公開時刻」を追加しています。日本時間で `HH:mm`（00:00〜23:59）を指定してください。時刻が空欄なら00:00です。時刻だけを指定することはできません。終了日は従来どおり、その日の日本時間の終わりまでです。

予約時点では枠を確保しません。開始日時になった時点のプランと公開件数を再確認します。

- 枠がある：公開します。
- 枠がない：公開せず、求人管理に「掲載上限により公開できません」のアラートタグを表示します。
- 同時刻に複数の予約がある：開始日時・ID順で枠を割り当てます。同時操作でも上限を超えないよう企業単位でロックし、枠は募集区分ごとに割り当てます。
- 終了済み・削除済み・非公開の求人は枠を使いません。
- 停止した求人は、枠が空いても自動では再公開しません。求人管理で編集し、公開の設定で保存してください。保存時に再判定し、成功するとアラートが消えます。

バックエンドは起動後10秒から、約30秒間隔で予約を確認します。サーバー停止中は公開せず、復旧後に再判定します。求人管理の取得時にも確認します。公開一覧・詳細・通常の応募からは、未公開・停止中の求人を利用できません。

求人管理は30秒ごとに表示を更新し、「掲載状態を更新」でも更新できます。予約公開／公開停止は操作履歴にも記録します。

## プラン情報

- `m_company_publication_plan`：プランコード・名称・求人募集の公開上限 `job_publication_limit`・企業募集の公開上限 `company_publication_limit`。旧 `publication_limit` は互換用で、新処理では参照しません。
- `t_company_publication_subscription`：企業とプランの対応
- `t_company_recruitment.publication_status`：DRAFT／SCHEDULED／PUBLISHED／BLOCKED／EXPIRED
- `publish_at`：日本時間の入力から変換した予約日時（timestamptz）
- `publication_blocked_at`：上限超過で止まった日時

企業自身からプランや上限を書き換えるAPIは追加していません。今後の有料プランは、このテーブルへ追加して対応できます。有料プランの購入・決済・プラン変更画面は今回の追加には含みません。料金案・割引計算は保持し、求人募集の無料判定は3件までです。現在利用できるのは無料プランです。

APIは既存の作成・更新を保持し、`publicationMode=AUTO|PRIVATE|SCHEDULE` を追加しています。確認用は `POST /api/platform-auth/company-recruitments/publication-check?jobId=...` です。最終的な可否は保存時に再確認するため、この確認結果だけでは枠を確保しません。

以後、SQLで直接追加した求人は既定で非公開です。以前のダミーデータSQLを使用する場合、初回は004より前に投入するか、投入後に求人管理から公開してください。

## 前回の「合計3件」版を適用済みの場合

今回の修正版SQLを改めて全文実行してください。既存テーブルへ区分別の上限列を追加するため、前回のSQLだけでは新バックエンドを使用できません。004というファイル名は同じですが内容を更新しています。

以前の上限で公開停止になった募集は、自動では再公開しません。空いている区分の枠を確認し、求人管理から編集・保存してください。

テスト専用の `src/test/resources/publication/shared_limit_v1.sql` は、旧スキーマからの移行試験用です。実際の適用にはdb/004の修正版を使用してください。
